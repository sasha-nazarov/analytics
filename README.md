# Документация по скрипту расчёта часов и дедлайнов (Оценка Q4)

## 1. Назначение
Скрипт автоматизирует:
1. **Подстановку часов** при изменении грейда, вида объекта или вида работ.
2. **Расчёт дедлайнов** с учётом приоритетов, сложности и параллельной работы аналитиков, разработчиков и тестировщиков.

---

## 2. Источники данных
- **Оценка Q4** — основной лист с задачами, аналитиками и оценками.
- **Затраты по грейдам** — таблица с нормами времени для комбинаций `Грейд × Вид объекта` (создание/рефактор).

---

## 3. Основные столбцы листа `Оценка Q4`
- C: Грейд  
- H: Вид объекта  
- I: Вид работ (Создание / Рефактор)  
- J: Сложность  
- K–M: Часы (БА / Разработка / Тестирование)  
- G: Приоритет  
- B: Аналитик  
- Q2: дата начала квартала  
- O–P: рассчитанные даты начала и готовности.

---

## 4. Автоподстановка часов
При редактировании C, H или I:
1. Формируется ключ `grade|objectType|workType`.
2. Из листа «Затраты по грейдам» берутся базовые значения.
3. Применяется коэффициент сложности:
   - Очень сложный — 1.6
   - Сложный — 1.3
   - Средний — 1.0
   - Лёгкий — 0.7
   - Очень лёгкий — 0.4

Формулы:
\[ BA = base_{BA} \times coeff, \quad TEST = base_{Test} \times coeff \]
`development` берётся без корректировки.

---

## 5. Расчёт дедлайнов (Smart Deadlines)
Модель симулирует работу аналитика по дням:
- В день доступно `WORK_HOURS_PER_DAY = 6.5` ч.
- Применяется буфер `1.25`.
- Параллельно выполняется до `3` задач БА, разработка и тестирование — без ограничений.
- Выходные пропускаются.

### Этапы:
1. Активируются задачи БА по приоритету (Максимальный → Низкий).
2. Рабочее время дня делится между активными задачами.
3. После завершения БА задача сразу переходит в DEV, затем TEST.
4. Все стадии работают параллельно, без очередей.

Формулы распределения:
\[ h_{BA} = \frac{6.5}{N_{BA,active}}, \quad h_{DevTest} = \frac{6.5}{N_{Dev}+N_{Test}} \]

Завершённые задачи фиксируют даты начала (O) и готовности (P).

---

## 6. Конфигурация и лимиты
- Рабочие часы в день — 6.5
- Буфер — 1.25
- Одновременные БА — 3
- Лимит расчёта — 365 дней

---

## 7. Использование
- Редактирование C, H или I → автоподстановка часов.
- Ручное обновление всех строк: `updateAllHours()`.
- Пересчёт дедлайнов: меню **Workload Tools → Calculate Smart Deadlines**.

---

## 8. Ошибки и проверки
- Пустые ключевые поля → часы очищаются.
- Нет правила → часы очищаются.
- Неверная дата в Q2 → ошибка.
- Пропускаются выходные и пустые строки.

---

## 9. Возможные улучшения
- Учет сложности для разработки.
- Добавление конфигурационного листа.
- Учёт отпусков.
- Более точное распределение времени (вес задач).
